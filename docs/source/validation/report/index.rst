===================
Validation coverage
===================

What this repository's :doc:`validation documents <../index>` claim, gathered into one place. The
figures below are a *summary of claims*, not a proof of them: they say who has vouched for which
files under which methodology, and whether the signatures and hashes still hold as of the run that
wrote this page. To be sure of any line of it, run the check yourself:

.. code-block:: sh

   freeports-validate check-grants

The assertions this repository grants are the prose ones under
``docs/source/validation/assertions/`` — statements about the software that a person read,
understood and agreed with, recorded under :doc:`agreement and good faith
<../methodologies/agreement_and_good_faith>`. A grant of one of them is a claim about a *statement*,
not about any bytes a program wrote, which is what separates it from the methodologies a formats
repository uses.

`Open the coverage page: the three viewpoints as tabs <../coverage.html>`_

.. note::

   That page is a single generated HTML file published beside this site, the same arrangement the
   :doc:`Rust API <../../rustdoc>` uses. It is **not** rebuilt with the site: whether a signature
   is valid is computed from the keyring of whoever runs the command, and a documentation builder
   has no public keys in it — so a page generated there would announce that every grant in the
   repository is invalid. It is written by the commit hook, on a machine that holds the keys, and
   committed under ``docs/source/_extra/validation/``. Building the site only copies it.

Keeping all of it current
=========================

The badges in the README, the summary block above and the six pages are all functions of what
``validation/`` claims, so a commit that changes a granted file and leaves them alone publishes
figures that are already wrong. ``.githooks/pre-commit`` regenerates them and stages what it
rewrote, and never refuses a commit over it: a committer with no network still has to be able to
commit.

By hand, it is one walk of the repository rendered several times — ``make validation-report``, or
the commands that target spells out.
