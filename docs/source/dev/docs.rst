=========================
Documentation development
=========================

The documentation is a `Sphinx <https://www.sphinx-doc.org/>`_ site in ``docs/``, with sources in
``docs/source``. Three kinds of content live there, and they are written differently.

**Prose** — the :doc:`whitepaper <../whitepaper/index>` and this developer section. New prose is
written in Markdown, with `MyST <https://myst-parser.readthedocs.io/>`_ enabled, so a Sphinx
directive is a fenced block:

.. code-block:: markdown

    ```{toctree}
    :maxdepth: 2

    problem
    install
    ```

Older pages are reStructuredText and stay that way; there is no campaign to convert them.

**The Python API** — generated by ``autosummary`` from the installed packages themselves, so it
cannot drift. It really imports them, which is why building the docs requires the extension module
to be built.

**The Rust API** — generated by ``cargo doc`` and published *beside* the site under ``/rustdoc/``,
not transcribed into ``.rst``.

Building
========

.. code-block:: console

    pip install -r contrib/requirements.docs.txt
    make -C docs rustdoc html

The result is ``docs/build/html/index.html``. ``make html`` on its own skips regenerating rustdoc,
which is what you want while editing prose. ``make -C docs rustdoc`` puts ``cargo doc`` output into
``docs/source/_extra/rustdoc/``, from where Sphinx copies it into the site verbatim.

Read the Docs runs the same steps — its ``pre_build`` job is that same ``make -C docs rustdoc`` —
so a build that works locally is a build that publishes.

To build one language:

.. code-block:: console

    sphinx-build -b html -D language=it docs/source docs/build/it

Generated output — ``docs/build/``, ``docs/source/_generated/`` and ``docs/source/_extra/`` — is
ignored by git. It is produced by a build, and a build product in version control goes stale the
moment someone forgets to regenerate it.

.. warning::

   The pages under ``validation/`` are **content-addressed**: their SHA-256 hashes are recorded in
   signed validation documents, in this repository and in others. Editing one — even fixing a typo
   — invalidates every grant that cites it. Changing them is a deliberate operation that includes
   re-granting and re-signing, not an act of tidying. See :doc:`../whitepaper/validation`.
