============================
Where each figure comes from
============================

A percentage is an answer to "how much"; this is the answer to "which". Each measurement already
carries the detail it was computed from — coverage per file, lint findings per rule, docstrings per
object — and this page lays it out worst first, which is the order somebody fixing it would work in.

**Only the worst few lines of each metric appear here.** The crate alone breaks down into more than
a hundred files, and a page listing every one of them changes in every commit that moves any of
them: a committed file whose diff nobody can read is a committed file nobody reads. The complete
detail is one command away and is never truncated:

.. code-block:: console

   freeports-dev ci-report --format json | jq '.metrics[] | select(.metric == "tests.rust.lines") | .breakdown'

How many lines a document shows is a setting, in the three tiers everything else here uses —
``--breakdown-limit N``, then ``FREEPORTS_CI_BREAKDOWN_LIMIT``, then ``report.breakdown_limit`` in
``ci.yaml``, then fifteen. ``0`` means all of them.

.. note::

   A breakdown line is not a target. A file at 0 % may be a thin wrapper around code that is
   thoroughly tested elsewhere, and a lint rule with forty hits may be one pattern used forty times
   on purpose. The list says where to look, not what to change.
